## Claude Code-Specific Notes

### Skill discovery gap

The skills under `.agents/skills/` follow the Codex repo-local convention and are NOT auto-discovered by Claude Code in this repo. Currently:

- `memory-review` — public, shipped via the npm package
- `openrelix-product-design-harness`
- `openrelix-technical-design-harness`
- `openrelix-implementation-harness`
- `openrelix-verification-compliance-harness`

If you need to follow one of these workflows from Claude Code, open the corresponding `SKILL.md` and use it as guidance — it will not appear in `/<skill-name>` autocomplete. Cross-host skill discovery is a known preview gap; see `docs/system-overview.md` "Skill loading model".

### Host-context memory block

`~/.claude/CLAUDE.md` contains an OpenRelix-managed block bounded by:

```
<!-- openrelix:shared-memory:start -->
... bounded personal memory summary ...
<!-- openrelix:shared-memory:end -->
```

That block is regenerated by `scripts/sync_host_memory_summary.py`. Do not hand-edit content inside the markers — it will be overwritten on the next sync. Content outside the markers is preserved.

### Worktree branch prefix

Per `AGENTS.md`, feature work uses a dedicated worktree. When operating from Claude Code, prefer branch names like `claude/<task-name>` so they are distinguishable from Codex's `codex/<task-name>` in `git log` and worktree listings.
